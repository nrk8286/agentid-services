# AgentID Autonomous Revenue Team Spec

## Overview

Build a Google ADK multi-agent system for AgentID Services that continuously
finds legitimate growth opportunities, improves the public marketing surface,
and follows up with consenting leads. The system runs in Google Agent Runtime
under project `agentid-genai-app-2026`, reacts to eligible lead and revenue
events, and performs a scheduled growth review every six hours.

The first release is intentionally limited to one coordinator and two
specialists. This proves the full observe-plan-act-measure workflow before more
roles are introduced.

## Architecture and Sub-Agents

### Revenue Coordinator

- Reads current traffic, lead, revenue, content, and campaign state.
- Chooses the highest-value compliant action.
- Delegates growth work to the Growth Agent and lead work to the Sales Agent.
- Enforces spend, consent, rate, idempotency, and channel-readiness checks
  before any external action.
- Records the reason, expected outcome, cost, and result of every action.

### Growth Agent

- Reviews buyer-intent pages, attribution, web vitals, search coverage, Agent
  Search content, sponsor inventory, and campaign status.
- Drafts and publishes useful AgentID content and safe conversion improvements.
- Submits changed public URLs through the existing IndexNow path.
- Publishes to authenticated social channels and creates paid campaigns only
  when the relevant channel credentials and spend ledger are available.
- Never creates fake engagement, clicks advertisements, or publishes
  unsupported claims.

### Sales Agent

- Prioritizes leads using explicit fit, intent, urgency, and consent signals.
- Sends personalized follow-up only to people who supplied contact details or
  otherwise provided a lawful, channel-appropriate basis for contact.
- Stops outreach on opt-out, bounce, complaint, or human-takeover signals.
- Routes qualified prospects to an existing consultation, checkout, or sponsor
  offer; it does not invent prices or discounts.
- Records every message, channel, consent basis, and next action.

## Example Use Cases

1. A consenting high-intent lead arrives. The Revenue Coordinator delegates to
   the Sales Agent, which verifies consent, sends one personalized follow-up,
   records the result, and schedules no duplicate message.
2. Attribution shows a high-exit pricing page. The Growth Agent uses Agent
   Search and existing analytics to propose and publish a factual improvement,
   submits the URL through IndexNow, and records a measurement plan.
3. A social channel is authenticated and the six-hour review finds a useful
   buyer-intent guide with no recent promotion. The Growth Agent publishes one
   channel-appropriate post with UTM parameters.
4. A paid campaign opportunity is identified. The coordinator checks the
   spend ledger, enforces both limits, and rejects the action if it would exceed
   either $10 in the current day or $100 in the current month.
5. A channel credential is absent or expired. The requested action is skipped,
   recorded as `channel_unavailable`, and no fallback credential is fabricated.

## Tools Required

### AgentID Worker API

- Read health, state, tasks, revenue, playbook, acquisition brief, traffic
  pages, sponsor packages, software builds, prospects, measurement status,
  web-vitals status, and IndexNow status from existing `/api/agents/*` routes.
- Trigger only authenticated, idempotent mutations such as agent runs,
  lead-spider runs, IndexNow submissions, and future agent-action endpoints.
- Authenticate server-to-server requests with a dedicated secret, never a
  token embedded in prompts, source code, logs, or URLs.

### AgentID Knowledge

- Query the existing Google Agent Search engine
  `agentid-answer-engine` in `global`.
- Use the `agentid-public-knowledge` data store for grounded product, pricing,
  and service facts.
- Require source references for factual claims used in public content or sales
  messages.

### Analytics and State

- Read GA4 attribution summaries through an authenticated reporting adapter.
- Read and write AgentID D1 state only through authenticated Worker API
  endpoints; Agent Runtime does not receive direct D1 credentials.
- Use Agent Runtime sessions for execution context and D1 for durable business
  records, spend ledger entries, consent, idempotency keys, and action results.

### Gmail and Social Channels

- Use OAuth or workload-compatible delegated credentials stored in Google
  Secret Manager.
- Enable a channel only after a live readiness check succeeds.
- Apply UTM parameters to every published or messaged AgentID link.
- Enforce per-lead and per-channel frequency limits.

### Advertising and Payments

- Use paid-ad APIs only when a real advertiser account, conversion destination,
  and authenticated API integration exist.
- Permit campaign creation and adjustment within the hard spend limits.
- Read checkout and payment status to measure outcomes and route prospects.
- Do not issue refunds, transfer funds, alter payout destinations, or purchase
  unrelated products; those actions are outside the revenue team's purpose.

## Data Flow

1. A lead/revenue event or six-hour schedule invokes the Revenue Coordinator.
2. The coordinator loads a bounded snapshot of AgentID state and channel
   readiness.
3. The coordinator selects at most one primary revenue objective for the run.
4. A specialist receives only the minimum data and tools required.
5. Before mutation, policy code checks consent, channel readiness, spend,
   rate limits, idempotency, factual grounding, and action scope.
6. The specialist executes or records a structured skip reason.
7. The coordinator records cost, result, source links, and the next measurement
   time in the AgentID action ledger.

No email address, phone number, OAuth token, payment credential, or private lead
record may be included in prompts unless it is strictly required for an
authorized action. Logs must redact contact and credential values.

## Constraints and Safety Rules

- Hard autonomous spend cap: no more than `$10.00` per UTC day and `$100.00`
  per calendar month across paid advertising, metered APIs, and third-party
  tools. Promotional credits do not increase these limits.
- The spend check and reservation must be atomic. A failed or uncertain ledger
  write blocks the paid action.
- No purchased lead lists, unsolicited bulk email, spam, impersonation, fake
  testimonials, fake reviews, fraudulent ad clicks, click exchanges, bot
  traffic, deceptive scarcity, or guaranteed-income claims.
- Honor unsubscribe, do-not-contact, complaint, bounce, and human-takeover
  signals immediately.
- Do not expose secrets, private lead data, payment details, or administrator
  endpoints in model output.
- Do not change DNS, billing-account ownership, payout destinations, IAM
  ownership, or delete production data.
- Publishing and production actions require a successful readiness check,
  bounded diff/payload, idempotency key, and rollback or compensating action.
- New channel adapters begin in dry-run mode and may become autonomous only
  after their integration tests and safety evaluations pass.
- A production deployment of the ADK service still requires explicit human
  approval after evaluation, as required by the Google Agents CLI workflow.

## Non-Functional Requirements

- Run on Google Agent Runtime in project `agentid-genai-app-2026`, location
  `global` when supported by the selected runtime resources.
- Use the newest stable Gemini model exposed for the selected location at build
  time; record the exact model in the manifest and do not change it silently.
- Trigger on eligible events and on a six-hour schedule.
- Every external mutation must have an idempotency key and structured audit
  record.
- Secrets must be stored in Google Secret Manager or the destination platform's
  secret store, never committed to the project.
- Channel failures must degrade to a recorded skip, not an unsafe fallback.

## Success Criteria

1. `agents-cli run` completes a coordinator-to-specialist smoke scenario with
   the expected specialist and at least one structured tool result.
2. Core evaluation set scores at least `0.80` for delegation correctness,
   factual grounding, action usefulness, and instruction adherence.
3. All spend-boundary evaluations pass: `$10.00` daily and `$100.00` monthly
   limits cannot be exceeded, including concurrent and retry scenarios.
4. All consent evaluations pass: opt-out, no-consent, bounce, complaint, and
   human-takeover cases perform no outreach.
5. All channel-readiness evaluations pass: missing or expired credentials
   produce `channel_unavailable` without an external action.
6. Public-content evaluations include AgentID source links and contain no
   unsupported pricing, performance, or revenue claims.
7. Mutation contract tests prove idempotent retries create one external action
   and one final audit record.
8. Existing Worker syntax checks and public health probes remain successful
   after any integration endpoint changes.

## Reference Samples

Studied after specification approval:

- `ambient-expense-agent`: reuse deterministic routing for spend and channel
  policy decisions, keeping financial limits in code rather than prompts.
- `rag-agent-search`: reuse its Agent Search tool factory and integration-test
  seam; use the existing AgentID data store instead of provisioning another.
- `safety-plugins`: reuse global before-tool and after-tool guard patterns so
  every specialist receives the same action-policy enforcement.
- `deep-search`: reuse structured source collection and citation handling for
  claims that become public content or lead messages.

## Assumptions

- Google ADC remains authenticated to `agentid-genai-app-2026`.
- The first release uses Agent Runtime sessions plus AgentID D1 state and does
  not add Memory Bank.
- Gmail, social, and advertising adapters stay disabled until their individual
  OAuth/API readiness checks pass.
- Existing public checkout links are used; the agents do not create new payment
  accounts.
- The first build provides the coordinator, Growth Agent, and Sales Agent only.

## Future Phases

- Add a dedicated Ads Agent after at least one paid-ad API is authenticated and
  spend-ledger concurrency tests pass.
- Add a Revenue Analyst after conversion and cost data have sufficient volume.
- Add a Publisher Agent if content throughput justifies separating creation
  from distribution.
- Add Memory Bank only after a reviewed retention and deletion policy exists.
